# How the library evolved

## The story in short

**The useful unit turned out to be one skill for the task at hand, not one file for every piece of research.** On January 17, 2026, the repository held [two notes about what to build](https://github.com/that-in-rust/agent-room-of-requirements/tree/44281b992b21669ead3b831975c015eda7ca6cc0). By November 23, a workshop participant could use [one index](../skills-for-engineering-teams/README.md) to choose among 18 subject skills and nine Rust skills. The November merge took the tree from **993 tracked files to 120**; it did not take the earlier editions out of Git.

Three decisions explain the change. First, package the **method** from an investigation so someone else can run it. Second, distinguish the **reference a reader needs** from the records of how it was written. Third, **merge by task** without removing context a skill needs when loaded alone. The dates below are commit dates; the historical links open the editions discussed, not today's files.

## 1. Research became reusable when it told the next person what to do

**January–February 2026.** The [first commit](https://github.com/that-in-rust/agent-room-of-requirements/commit/44281b992b21669ead3b831975c015eda7ca6cc0) paired OpenEnv challenge research with a shortlist of Rust library ideas. A question from this period illustrates what the repo was good for: *could Ruby become a Rust binary?* The [February 3 feasibility study](https://github.com/that-in-rust/agent-room-of-requirements/blob/d7df302f44aaa1d7cc3672bf342546614e32b488/zzArchive/Ruby-to-Rust-Transpiler-Research.md) considered a general transpiler. The [February 4 Rails thesis](https://github.com/that-in-rust/agent-room-of-requirements/blob/dd485a4d2c65d9ba83844dce62d372c8369e9d1f/referenceRepo/zzArchive/RubyRust202601/06-Thesis-Rails-DSL-Compiler-to-Rust.md) narrowed the target to schemas, models and routes. These were competing scopes for a product, not evidence that a converter shipped.

Alongside those investigations, [A01](https://github.com/that-in-rust/agent-room-of-requirements/blob/e635732911065f84d8dca7d6084d70ab14707af2/A01-LLM-Workflow01.md) made a distinction a second team could use immediately: a production bug needs a regression test, not the discovery process for a new product. [A00](https://github.com/that-in-rust/agent-room-of-requirements/commit/8997ec3bad9f910d7c1775f5a4f0d962d649ecad) set out the principles. The [February 27 skill packs](https://github.com/that-in-rust/agent-room-of-requirements/commit/fa5f279d8bf8ae2b560b81693532d42a01494054) went a step further: the [executable-spec skill](https://github.com/that-in-rust/agent-room-of-requirements/blob/fa5f279d8bf8ae2b560b81693532d42a01494054/agents-used-202512/executable-specs-01/SKILL.md) asked for a stable requirement ID, an observable outcome and a test that could reject it. A new team could use that procedure without reading the investigation that preceded it.

**March–May.** Skills began carrying the tools needed to do the job. The [March dependency mapper](https://github.com/that-in-rust/agent-room-of-requirements/tree/c385db16df831c446c677266110c6421fa12d9de/agents-used-202512/dependency-map-cli-tools-01) shipped scripts for mapping a checkout and reading a code span. The [April GitHub context pack](https://github.com/that-in-rust/agent-room-of-requirements/tree/d90c79aa4e394ce43f05936a4a7afb4b348fe5b6/skills/capture-github-repo-context) collected the surrounding repository discussions and artifacts. The repo also [removed a large research and journey archive](https://github.com/that-in-rust/agent-room-of-requirements/commit/319f2c73aba519a58f543ee6785f6860a7e716cc), [repackaged Claude agents as Codex skills](https://github.com/that-in-rust/agent-room-of-requirements/commit/65c60d3c87ed86573a0482e7ebbbd2d639e98251), and [rewrote the root guides with diagrams](https://github.com/that-in-rust/agent-room-of-requirements/commit/e1a7d2368861a4bd32e2bc2c176ea1d0e2581628). The distinction was emerging: keep a procedure easy to teach; keep a project investigation retrievable on its own terms.

## 2. Expanding the references exposed two different readers

**July.** [A02](https://github.com/that-in-rust/agent-room-of-requirements/blob/f609eeb2c4f202d2b528d08f09c6c17bb6ca9306/A02-Mega-Idiomatic-Prompt.md) asked for more than a list of idioms: *which default should I use, when does it fail, and what evidence supports it?* The [June-labelled corpus was committed July 6](https://github.com/that-in-rust/agent-room-of-requirements/commit/70ad86b7e7b2f3b419c0fe18a577752cbd7b05e7). For the next edition, the [review specification](https://github.com/that-in-rust/agent-room-of-requirements/blob/bccfd6412a5d0efbb153a50e466806b8745117cb/idiomatic-reference-evolution-spec-202607.md) assigned one owner per file and ten questions per section. The [July 20 merge](https://github.com/that-in-rust/agent-room-of-requirements/commit/bccfd6412a5d0efbb153a50e466806b8745117cb) recorded completion of the 99-reference corpus.

The maintainer resuming that work needed the queue, question packets and checkpoint. The practitioner trying to write a memo needed the writing advice. The [July handoff](https://github.com/that-in-rust/agent-room-of-requirements/blob/bccfd6412a5d0efbb153a50e466806b8745117cb/IDIOMATIC_REFERENCE_EVOLUTION_HANDOFF_202607.md) already named the problem: readers should not have to choose among 99 files. Its proposed second pass was a **plan**; the [August 16 reorganization](https://github.com/that-in-rust/agent-room-of-requirements/commit/117afc24bfca1acea5a3bc0dc81afa2ef4faaaff) made a different, intermediate move. Its [design note](https://github.com/that-in-rust/agent-room-of-requirements/blob/117afc24bfca1acea5a3bc0dc81afa2ef4faaaff/docs/plans/2026-08-16-repository-top-level-cleanup-design.md) explicitly kept the 99 filenames and put the review evidence under `projects/`. August made things easier to locate; it did not yet reduce the number of references a reader had to choose from.

## 3. Consolidation changed what readers load, not just where they look

**November 14–17: Rust showed why shorter is not always better.** The Rust work [narrowed the source set to documents actually about Rust](https://github.com/that-in-rust/agent-room-of-requirements/commit/8442003bb66652208ae87995ad3839d675ca196e). The [source inventory](https://github.com/that-in-rust/agent-room-of-requirements/blob/0dc7115c1a395945d6872fff35ef234e1c9a2f08/Rust-skills/README.md) describes how 56 inputs fed one large guide covering everything from ownership to Tauri. The [Tauri pilot](https://github.com/that-in-rust/agent-room-of-requirements/commit/616986e6dbbb86a49953e70601d5385298a9ab65) reversed the reader’s burden: load one task-specific skill, with the common rules already inside it. A script updates those blocks from one source. The [nine-skill Rust index](https://github.com/that-in-rust/agent-room-of-requirements/blob/894c5fac1aee886a6fd11b4acd668ee8df2c4750/Rust-skills/skills/README.md) is the result. A CLI author no longer needs to read the desktop-app guide; neither author loses the shared rules.

**November 18–23: the library used its own specification method.** [A03’s outside-in revision](https://github.com/that-in-rust/agent-room-of-requirements/commit/0dc7115c1a395945d6872fff35ef234e1c9a2f08) kept an outer behavioral test as the goal and used faster inner tests to guide implementation. The [reduction declaration](https://github.com/that-in-rust/agent-room-of-requirements/commit/9cbeeaad0c984fb181fa3412781f61db7a2649a5) set the acceptance criteria before the cleanup: a file ceiling, a discoverable skill per subject, unchanged root guides and an embedded core in every Rust skill. The [November 23 merge](https://github.com/that-in-rust/agent-room-of-requirements/commit/c1c174e64657a0f9302802a103f262b4907f7011) delivered the [subject index](https://github.com/that-in-rust/agent-room-of-requirements/blob/c1c174e64657a0f9302802a103f262b4907f7011/library/README.md) and kept [upstream originals and their licenses](https://github.com/that-in-rust/agent-room-of-requirements/blob/c1c174e64657a0f9302802a103f262b4907f7011/library/third-party/ATTRIBUTION.md) separate. The file count is verifiable from the two Git trees; whether a rewritten paragraph preserves an important idea is a matter of editorial review, not something the count proves.

Two examples show what “merged” meant in practice:

| Reader’s task | Before | After |
|---|---|---|
| Explain a decision | The [March Minto guide](https://github.com/that-in-rust/agent-room-of-requirements/blob/d672d17513f2b3fbf25971004aaf0043b0f58776/agents-used-202512/minto-pyramid-01.md) taught answer-first writing; the [July reference](https://github.com/that-in-rust/agent-room-of-requirements/blob/bccfd6412a5d0efbb153a50e466806b8745117cb/idiomatic-ref-202607/minto_pyramid_writing_patterns-20260710.md) expanded it. | [Structured writing](https://github.com/that-in-rust/agent-room-of-requirements/blob/73ef22d78309345c6c20ec3d156f7ce3ff90a684/library/skills/structured-writing/SKILL.md) starts with the reader’s question and uses the pyramid to structure the answer. |
| Navigate an unfamiliar codebase | The mapper and GitHub pack above were separate choices; [Strata](https://github.com/that-in-rust/agent-room-of-requirements/tree/02862b43c80b06be41aceea62ee219c4c9be752e/agents-used-monthly-archive/codex-skills-202607/strata-202607) was another. | [Codebase navigation](https://github.com/that-in-rust/agent-room-of-requirements/commit/0bca3f0d31b35bdd4c3f89954b14373d7a9c10a6) put the choices and their helper scripts together. A workshop can start with the question about the code, not the name of a tool. |

**November 23, after the reduction: start from the reader’s task.** The skills already existed, but a participant still had to choose between two shelves: `Rust-skills/` and `library/`. The [workshop layout change](https://github.com/that-in-rust/agent-room-of-requirements/commit/e2d2f5dfcca4565b6d17016b8719a69e048ea7ef) put all 27 behind one task index. The [walkthrough](../how-to-use-skills/README.md) now takes a reader from mapping the repo to observing a failing check and fixing it. The 120-file limit belonged to the migration, not the workshop; ongoing checks focus on whether readers can reach the skills and whether the Rust guidance stays in sync.
